# Drone flyby development

## V1 history (current commands are in the V2 section below)

- `example.py` is the untouched official baseline. The API serves `solution.py`, with ONNX inference in `detector.py` and image-based motion estimation in `motion.py`.
- Runtime inference must not read reference frames, annotation files, or scene metadata, and must not make external API calls. The container intentionally includes only runtime code and `weights/detector.onnx`.
- The local Python 3.12 environment is `.venv-ml`. Start the API with `.venv-ml/bin/python api.py` from this directory. The system Python is 3.14 and does not have the project dependencies.
- Run software correctness checks with `.venv-ml/bin/python -m unittest -v test_solution`. These tests use generated images and stub predictions, not challenge accuracy measurements. After training and export, `.venv-ml/bin/python -m unittest -v test_artifact` checks export parity and the real endpoint using generated inputs only. TestClient needs `httpx==0.28.1`, included in the training requirements.
- Training dependencies are in `requirements-training.txt`. The local GPU uses PyTorch 2.6.0 and torchvision 0.21.0 from the CUDA 12.4 wheel index.
- Train with `.venv-ml/bin/python train.py --steps 12000 --batch 2 --size 640`; export with `.venv-ml/bin/python export_model.py`. Training uses a custom loop without a validator, scorer, or scored checkpoint selection. The final EMA weights are used.
- `train.py` uses the supplied reference scenes only. It mixes real crops with class-balanced foreground copy-paste and randomized position, count, orientation, scale, background, color, and blur. `weights/detector.json` records training provenance. Adjacent reference frames are not an independent validation split.
- Unit tests, graph export, and synthetic-input interface checks are not evidence of a competition score or of generalization. Never claim measured detection accuracy without a separately authorized measurement.
- Do not run `local_evaluator.py`, remote verification, validation, or evaluation attempts unless the user explicitly authorizes them; the implementation session requested no attempts.
- Container verification works with rootless Podman: `podman build --pull=missing -t localhost/drone-flyby-local .`, then `podman run --rm --network none localhost/drone-flyby-local python -c "import api; from solution import initialize; initialize()"`. The offline startup check does not run a scorer. `.dockerignore` excludes training data, virtual environments, checkpoints, and dotenv files from the build context.

## V2: current runtime and iteration workflow

- Local scoring is now explicitly authorized. Do not initiate official remote validation or the one-shot evaluation without further explicit authorization.
- Training runs locally on an MX570 with 2 GB VRAM. The separate approximately 24 GB GPU machine is available for validation only, not training. Local laptop timing is not deployment timing.
- `api.py` now serves `submission.py`. The selected model is `weights/flyby_v2.pt`; `weights/flyby_v2.runtime.json` contains inference-only settings and the weight checksum. `weights/flyby_v2.json` contains provenance, local measurements, and their limitations. The original baseline and V1 weights are retained.
- Install `requirements-gpu.txt` on the inference machine, or `requirements-training.txt` for training and benchmark dependencies. The tested torch/torchvision CUDA versions remain 2.6.0/0.21.0 (CUDA 12.4). Python 3.11 and 3.12 are supported by the supplied environments.
- Start with `.venv-ml/bin/python api.py`. Defaults: `cuda:0`, canonical input width 1920, confidence 0.05, full-view policy, no flip ensemble. Settings may be overridden with `DRONE_MODEL_PATH`, `DRONE_DEVICE`, `DRONE_INPUT_WIDTH`, `DRONE_CONFIDENCE`, `DRONE_CAMERA_POLICY`, and `DRONE_TTA` (`none` or `flip`). CPU mode is for debugging, not the recommended submission configuration. Use one server worker to preserve sequence state.
- Input width controls the physical scale seen by the network, not just computational cost. The current weights were trained at source scale 0.5, corresponding to full-view width 1920. Rebenchmark changes rather than assuming larger inputs improve accuracy. Zoomed views are resampled to the same physical scale.
- Runtime disables Ultralytics online checks and automatic dependency installation before importing it, requires existing local weights, and never uses reference annotations, reference imagery, or an external inference API.
- The V2 detector is a YOLO11s P2 model (strides 4/8/16/32), initialized from official DOTA-pretrained weights. Foregrounds use SAM 2.1 plus a class-independent mask-consistency check. Additional backgrounds are public-domain UC Merced/USGS imagery, with published archive SHA256 verification.
- Prepare assets with `prepare_data.py backgrounds`, then `prepare_data.py masks`, then `prepare_data.py validation`, using `.venv-ml/bin/python`. These are training-time downloads, not runtime downloads. A completed validation scene is not overwritten; use a different `--output` path for a genuinely new diagnostic.
- Training excludes reference frames `{1, 8, 15, 19, 24}` and uses 1,040 external background images. Another 260 backgrounds and the excluded views are reserved for the fixed 64-image synthetic transfer diagnostic. All views still contain the same object instances; neither this split nor the synthetic diagnostic is an independent real-world validation flight.
- Train a fresh run with `.venv-ml/bin/python train_v2.py --run .training/runs/new-run --steps 4000 --batch 2`. Continue the existing trained run with `.venv-ml/bin/python train_v2.py --run .training/runs/dota-p2s-clean --steps 12000 --batch 2 --resume`. `--steps` is the total target step count. Keep architecture, seed, batch, accumulation, scale, and schedule options consistent when resuming. EMA inference snapshots are saved every 1,000 steps; `resume.pt` also includes the optimizer, scaler, training weights, EMA, and RNG states.
- The selected checkpoint is step 8,000. Single-pass local mAP50: Helsinki 0.898594, five held-out frames 0.878713, synthetic transfer 0.917834, mirrored Helsinki 0.898902, dimmed Helsinki 0.895851. Flip fusion reached 0.901862 on Helsinki and 0.919445 on transfer, but is optional because the gain was small and it approximately doubles inference work. These are offline accuracy measurements, not an official competition score.
- Benchmark the packaged defaults with `.venv-ml/bin/python benchmark.py --output .training/current.json`. Use `--data-root .training/validation --scene heldout --stateless` or `--data-root .training/validation --scene transfer --stateless` for the two diagnostics. Use `--transform flip`, `--transform dim`, or `--tta flip` for stress tests and inference ablations. Reports include per-class AP, predictions, settings, and timing. `analyze_errors.py REPORT --output IMAGE` produces localization/classification diagnostics for the reference scene.
- For the actual HTTP protocol, run `.venv-ml/bin/python local_evaluator.py --url http://127.0.0.1:9053/predict`; add `--realtime` on the deployment machine to measure the effect of frame skipping. `benchmark.py` and the API share the same predictor and camera policy.
- Package a selected checkpoint with `package_model.py --weights CHECKPOINT --reports REPORT...`; optional `--tta flip` changes its deployment profile. This writes the model, a provenance report, and a separate inference-only manifest. Do not package metrics from a different checkpoint as if they described the selected model.
- Run `.venv-ml/bin/python -m unittest -q test_solution test_v2 test_artifact`. Tests cover coordinates, camera constraints, sequence isolation, stale-track reset after long gaps, P2 loss/backpropagation, physical-scale preservation, flip restoration/fusion, package integrity, and API requests with external HTTP calls blocked.
- Build with `podman build -t localhost/drone-flyby-v2 .` (or Docker). The image contains the trained weights and runtime manifest, but no training data or evaluation annotations. An offline CPU startup check is `podman run --rm --network none -e DRONE_DEVICE=cpu localhost/drone-flyby-v2 python -c "from submission import initialize; initialize()"`. For NVIDIA Docker deployment, expose the GPU with `--gpus all` and the service with `-p 9053:9053`.
